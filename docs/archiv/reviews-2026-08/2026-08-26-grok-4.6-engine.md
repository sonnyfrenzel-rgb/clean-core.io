## Critical

**1. Internal-table `INSERT` / `MODIFY` / `DELETE` are reported as database writes**  
`lib/abap/evidence-model.ts` (`processTableAccess` callers) and `lib/abap/code-assessment.ts` (`extractDataCoupling`)

```ts
const insertMatch = text.match(/^INSERT\s+(?:INTO\s+)?([\w\/]+)/i);
const modifyMatch = text.match(/^MODIFY\s+([\w\/]+)/i);
const deleteMatch = text.match(/^DELETE\s+(?:FROM\s+)?([\w\/]+)/i);
```

Trigger: `INSERT ls_wa INTO TABLE lt_vbap`, `INSERT LINES OF lt1 INTO TABLE lt2`, `INSERT INITIAL LINE INTO lt`, `MODIFY lt_mara FROM ls_mara`, `DELETE lt_itab WHERE ...`.

`lt_*` / `ls_*` are not Z/Y and not in `FAKE_TABLES`, so they become **Critical** “Direct Write to SAP Standard Table LT_VBAP” (or a write to `LS_WA` / `LINES` / `INITIAL`). That fabricates Critical counts, tanks the clean-core score, and can force Side-by-Side via `customWrites` / `standardWrites` in `extensibility-router.ts`. Distinguish `INSERT dbtab FROM` / `DELETE FROM dbtab` from `INTO TABLE` / `LINES OF` / `ADJACENT` / internal-table `MODIFY`.

**2. Released CDS access is flagged as an illegal standard-table read**  
`lib/abap/evidence-model.ts` (`processTableAccess`, non-custom branch)

Any `SELECT FROM <name>` where `<name>` is not Z/Y is a `standard-table-read` (High on public cloud). Released views are **not** in `MERGED_TABLE_MAP` (layer 2 only maps objects that have a successor), so the engine then invents `I_${table}`.

Trigger: `SELECT * FROM i_salesorder INTO TABLE @DATA(lt).` — the ABAP Cloud-correct pattern — is reported as “Direct Read from SAP Standard Table I_SALESORDER”, “hard break” in public cloud, replacement `I_I_SALESORDER`. Look up the FROM target in the Cloudification artifacts; `released` must not be a violation.

## High

**3. Namespaced customer objects are graded as SAP residual C (no heuristic fallback)**  
`lib/abap/abcd-classification.ts` (`isCustomerObject` / `gradeFromSapStates`)

```ts
return /^[ZY]/.test(n);
// ...
if (s.isSapObject) return { grade: 'C', provenance: 'catalog-residual' };
```

`/ACME/TABLE1` does not match `^[ZY]`, so `getSapObjectStates` sets `isSapObject: true`. Not in either SAP file → **C / `catalog-residual`**. Callers only fall back to `gradeFromCoupling` / `gradeFromInventory` on `Unknown` / `heuristic`, so they will **not** correct this. The comment that `/.../` is “not customer-owned” is wrong: registered customer/partner namespaces are the normal alternative to Z/Y. Same Z/Y-only test in `extractDataCoupling` / `processTableAccess` treats `/ACME/TAB` writes as standard-table Critical.

**4. `classicAPI` beats `notToBeReleased` and `deprecated`**  
`lib/abap/abcd-classification.ts` (`gradeFromSapStates`)

Order is: `released` → `classicAPI` → `noAPI` → `notToBeReleased` → `deprecated`. Released-over-classicAPI is correct. The other ~196 overlaps are not.

Trigger: an object with `releaseState: notToBeReleased` (or `deprecated`) **and** `classificationState: classicAPI` is graded **B**. That also skews `getPublishedGradeDistribution()` on the public census page. Confirm with the 196 shared keys; any non-`released` overlap is a wrong published number. Terminal release states should win after `released` and before classification.

**5. Two table catalogs disagree; the small one grades most SAP tables as A**  
`lib/abap/code-assessment.ts` (`STANDARD_TABLE_MAP`, ~25 keys) vs `lib/abap/catalog-service.ts` (`MERGED_TABLE_MAP`)

`extractDataCoupling`: not in the 25-name map and not Z/Y → `riskLevel: 'Low'` on reads. `gradeFromCoupling` maps Low → **A**.

Trigger: `SELECT * FROM acdoca` (or almost any unlisted SAP table) → A / cloud-ready if that path is used. `buildAbapEvidence` on the same source emits Medium/High `standard-table-read`. Delete the small map or derive `isStandard` / risk from the merged catalog + release state.

**6. Wrong curated successor is sticky**  
`lib/abap/sap-api-catalog.ts` (`VBKD`) + `lib/abap/catalog-service.ts` (layer 1 always overwrites and `noPath.delete`s)

`VBKD` (sales-document business data) is mapped to `I_SalesOrderItemPartner` (partners; that is `VBPA`). Curated wins over the official repo, so a bad row is shown as `confidence: 'curated'`. Fix the row (or stop overriding when the curated target contradicts the repo).

**7. Function-module / class / view usage is never classified**  
`lib/abap/evidence-model.ts` — `unreleased-api` is never emitted; no `gradeSapObject` / catalog lookup on `CALL FUNCTION`, classes, or the SELECT target.

The classification artifact exists to separate `classicAPI` (B) from `noAPI` (D). Trigger: `CALL FUNCTION 'an_unreleased_or_noAPI_fm'`. Today that is silent, while `SELECT FROM i_product` is High (finding 2). Wire lookups for FUNC/CLAS/DDLS/TABL names into findings and grades.

**8. Every FUNC successor is labeled `BAPI`**  
`lib/abap/catalog-service.ts` (`tadirToType`)

```ts
case 'FUNC': return 'BAPI';
```

Trigger: any Cloudification successor with `tadir: FUNC` that is not a BAPI. UI / audit pack show a BAPI that does not exist. Use `Function Module` unless the name/labels actually denote a BAPI.

**9. Default sync does not refresh `classicAPI` / `noAPI`**  
`scripts/sync-cloudification-repo.ts` (`main`: default `'latest'` only)

`classifications-sap` is a separate registry key. `npx tsx scripts/sync-cloudification-repo.ts` (no `all`) leaves B/D coverage stale while release states update — public A–D census and `gradeSapObject` drift. Default to `['latest', 'classifications-sap']` (or fail CI if either artifact is older than the other by more than one run). `getMergedCatalogVersion()` also hashes only the release file, so the audit-pack string cannot prove classification freshness.

## Medium

**10. SELECT parser misses ABAP’s usual join forms**  
`lib/abap/select-parser.ts` (`parseJoins`)

`joinRe` requires `INNER|LEFT|RIGHT|CROSS` before `JOIN`. Trigger: `SELECT ... FROM vbak JOIN vbap ON ... JOIN vbep ON ...` → `tableCount === 1`, no complex-join finding, no CDS match. Comma joins (`FROM vbak, vbap`) are also a single table. Evidence-model’s splitter already allows a bare `JOIN`; this parser should too.

**11. `SELECT-OPTIONS` is parsed as `SELECT`**  
`lib/abap/select-parser.ts` (`extractSelects`)

`\bSELECT\b` matches the `SELECT` in `SELECT-OPTIONS`. Trigger: `SELECT-OPTIONS s_matnr FOR mara-matnr.` → a fake SELECT in transformation SQL metadata / join detection. Require `SELECT` not followed by `-`.

**12. Missing customer parents are treated as resolved**  
`lib/abap/class-model-resolver.ts`

A missing `ZCL_*` / `ZIF_*` does not go into `missing` and does not set `blocks-resolution`; `YCL_*` and `/NS/CL_*` do. Trigger: local class `INHERITING FROM zcl_base` without `zcl_base` in the upload → `resolved: true`, deep-inheritance “fully”. Only treat `CL_*` / `CX_*` / `IF_*` (SAP prefixes) as optional.

**13. Inventory regexes drop real objects**  
`lib/abap/code-assessment.ts` (`extractCodeInventory`)

- `INTERFACE` requires a trailing space after the name → `INTERFACE zif_foo.` is skipped.  
- All names use `[\w]+` → `/NS/CL_FOO` never enters inventory (and never gets a heuristic grade).

**14. Last-write-wins catalog index ignores TADIR type**  
`lib/abap/cloudification-repo.ts` (`normalizeCrFile` / `normalizeClassificationFile`)

Keys are name-only. Trigger: same `tadirObjName` as `TABL` and `DDLS` (or two FUNC rows) — one state/successor silently replaces the other. Composite key `tadirObject + name` (and keep FUGR→`objectKey` as FUNC).

**15. Unhandled release states become level C**  
`lib/abap/abcd-classification.ts` + `lib/abap/cloudification-repo.ts` (comment lists `decommissioned` / `notReleased`)

Trigger: any artifact entry whose `state` is not exactly `released` / `deprecated` / `notToBeReleased` / `classicAPI` / `noAPI`. Confirm with a unique-`state` pass over both generated JSONs; unknown states must not be counted as residual C in `getPublishedGradeDistribution`.

**16. `I_${table}` is emitted as a CDS replacement**  
`lib/abap/evidence-model.ts` (standard read, `hasReplacement === false`)

Trigger: `SELECT FROM t000` (or any unmapped table) → `sapReplacement.objectName = 'I_T000'`, type CDS View, shown next to a catalog version. That is an invented object. Omit `sapReplacement` unless the merged catalog (or a verified candidate list) has a row.

**17. Measurement window is inferred from `lastUsed` min/max**  
`lib/abap/usage-parser.ts` (`detectPeriod`)

Trigger: a 12-month SCMON dump whose last-used dates span 3 days (or 8 years). `periodDays` / `measuredFrom` / `measuredTo` are shown as the measurement window. Leave them unset unless the file has real period columns; do not imply a window you did not read.

**18. `diffResultSets` ignores `opts.unordered`**  
`lib/abap/result-diff.ts`

Comparison is always multiset/JSON-key. Trigger: caller passes `unordered: false` to assert `ORDER BY` / `UP TO n ROWS` — ordered mismatches still `equal: true`. Honor the flag or remove it.
