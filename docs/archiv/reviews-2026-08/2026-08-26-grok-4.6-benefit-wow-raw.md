**The current card asserts the differentiator and proves the commodity.** The right column is already “proven, not claimed.” The left column is a designer’s credit-check story with a CSS-flex BPMN. A sceptical architect reads it as a mockup, which is fatal, because the left column is the only reason to stop.

The wow has to make the left column as undeniable as the numbers on the right — using only the public reference file and/or the free deterministic engine. No Gemini on the open internet, no 24h gate in the critical path, no scripted pipeline.

Five proposals. Ranked. One of them is clearly strongest.

---

### 1. Click any business sentence → the ABAP that licensed it
**(strongest — build this)**

**What they see/do.** The left column is no longer a static story. It is the frozen Gemini pyramid from the public reference run, shown next to the actual `.abap` (or a tight excerpt). Click “blocks delivery when the credit limit is exceeded” and the matching `SELECT` / `IF` / `MESSAGE` highlights. Click a BPMN task or a RACI row, same thing. Sentences the model inferred rather than read are visually marked as inferred — no highlight, or a distinct mark, with a one-line legend: *in the code* / *inferred*. A link sits under the pair: *file, run, signed pack*.

**Why it lands here.** This audience does not trust prose about Z-code. They trust correspondence. Signavio cannot do this (no code). smartShift and CoreAssess will not do this (they ship a backlog). The click is the proof that the left column is an output, not copy. Marking inference is the same move you already made with “2 of 11 construct classes handed back untouched.” It will get screenshotted in architecture reviews.

**Cost / what goes wrong.** Medium. You need a provenance map from the frozen run (byte ranges or statement IDs → pyramid nodes), a small highlight UI, and an honest inferred bucket. No new libraries. Failure mode: you highlight the wrong statements, or you mark inferred claims as grounded. That is worse than a mockup — it is a lie with a pointer. If today’s Gemini output does not carry spans, do not fake them; add spans on the next frozen run or don’t ship this. Second failure: the reference program is too toy-like and the correspondence looks planted. The file has to look like something they have inherited.

**Unprovable?** Only if you imply every highlighted span *caused* the sentence, or that the inferred steps are correct. The honest claim is: *these nodes were generated from this file; these ones cite these statements; these ones do not.* That is auditable. Do not say “explainability” or “grounded generation.”

This is the honest replacement for the transformation-replay you now regret. Same instinct (show work), none of the theatre.

---

### 2. Put the whole frozen pack in the card, not a teaser

**What they see/do.** The left column becomes a compact reader for the real five-level pyramid of the reference run: domain → process group → BPMN → task specs → SOP/RACI. Tabs or a short accordion, all pre-rendered from the signed pack. One control: *Source file*. They can read the SOP. They can disagree with it. Footer: *Draft from reference run &lt;hash&gt;, signed, dated. Correct it; don’t start from a blank page.*

**Why it lands here.** The objection to the current card is “you wrote a nice example.” A full SOP they can actually read kills that. Process owners finally see the artifact they would be asked to correct. Architects see you are willing to put a complete, imperfect draft on the public internet.

**Cost / what goes wrong.** Low. The pack already exists. Risk: the draft is mediocre or wrong in public, on the most expensive pixels you have. That is the brand, but only if the surrounding copy keeps saying *draft*. If the SOP reads like generic credit-management boilerplate, you have confirmed their suspicion. Also: a wall of text is not a wow if you dump all five levels at once. One level visible, the rest one click.

**Unprovable?** Calling it “the process” or “what the program does” — yes. Calling it “the draft this run produced for this file” — no.

Weaker than #1 because a long document can still be dismissed as written by hand. Traceability is what makes the document undeniable. Do #2 as the container for #1, not instead of it.

---

### 3. Named-object roll-call from the live parse

**What they see/do.** Under the right-column bar (or as a thin strip between the two questions), render the actual objects the reference parse just classified, by the names this audience dreams in: `KNKK`, `VBAK`, `BAPI_…`, whatever the file really touches. Each row: object → released successor or *no released API* or *handed back*. Computed at request time from the same file as the counts. No animation. Maybe a “recomputed just now” timestamp if you already re-parse per request.

**Why it lands here.** Recognition is the architect’s dopamine, not a percentage. They will forgive a plain page if they see a table they have fought with and a released successor they did not have at their fingertips. This is the deterministic engine speaking its native language, in public, with no API key.

**Cost / what goes wrong.** Low. You already have the mapping. Risk: the reference file is a greatest-hits of mappable objects and looks cherry-picked. Or the list is long and becomes a data dump. Cap it (top N by severity / unreleased-with-successor first) and link the rest to `/reference-analysis`.

**Unprovable?** The mapping, if it is SAP’s own released-API data, no. Any gloss like “ready to migrate” or “this is the work,” yes. Keep the three buckets you already use: settled / your call / hand work.

Weaker than #1 because it wows the right column, which is not your gap. It is the correct supporting proof that the engine is real. Ship it anyway; it is cheap and on-brand. It is not the moment.

---

### 4. Real BPMN 2.0, downloadable, not a flex row

**What they see/do.** Replace the toy circles with the actual BPMN XML from the frozen pack, rendered as a proper diagram (bpmn-js is a 2D viewer, not a 3D toy — acceptable if you keep it thin and server-render an SVG fallback). Button: *Download .bpmn*. Subtext: *opens in the modeller you already have*. Optional: the XML is in the signed pack, so the file they download is the file that was signed.

**Why it lands here.** Process owners live in Signavio. Architects have been burned by “process graphics.” A file they can open in their own tool is an artifact. A CSS row is a marketing slide. This is how you stop the “Signavio already does process” comparison: Signavio never emitted this from a Z-program.

**Cost / what goes wrong.** Medium. Viewer weight, mobile layout, and ugly auto-layout will all hurt you more than the current humble row. If the XML is incomplete or not schema-valid, the download is an own-goal. Do not promise “Signavio-ready” unless you have opened it in Signavio.

**Unprovable?** “This is the process” — yes. “This is the BPMN the run emitted; here is the XML” — no.

Weaker than #1 because a pretty diagram without provenance is still just a prettier mockup. Do this *after* clicks highlight source, or you have spent the complexity budget on drawing.

---

### 5. Ungated paste: deterministic half only, 40 lines, no Gemini

**What they see/do.** A small paste box: “40 lines. No login. No model. The engine that needs no key.” They paste. They get object→API rows, construct classes, and the same three buckets, plus the support-matrix line (*this snippet used 1 construct we hand back*). Hard cap, rate limit, no store, no business pyramid, one sentence on why the left column is not here: *that half calls Gemini and is gated; this half is the part we can give away*.

**Why it lands here.** “I put *my* code in and it spoke.” That is a real stop-scrolling moment for an architect who will never register for a 24h approval to see a demo. It also makes the free/gated split concrete instead of a pricing footnote.

**Cost / what goes wrong.** Medium-high, and the failure modes are ugly. Proprietary code in a marketing textarea is a compliance incident waiting for a screenshot. People will paste 4,000 lines, or malware, or an include that proves nothing. If the snippet is too small to classify, the output looks like a toy and you have spent the wow. If you then tease “register to see what it does,” you have turned the honest gate into a lead form. Abuse of the parse endpoint is cheaper than Gemini abuse but not free.

**Unprovable?** Implying the snippet result is what they will get on a landscape, or that the missing business half would have been good — yes. Showing a parse of what they pasted — no.

This is the only proposal that is *partly theatre-adjacent*: the paste box is a classic growth gimmick. It is justified only if the output is the real engine and the limitations stay loud. I would not put this on the benefit card. If you ever do it, it is a separate “prove the engine” strip below, after they already believe the left column.

---

### Not on the list, on purpose

- **HMAC “verify this signature” button.** Trust furniture. Auditors nod; everyone else sees a crypto badge. Mild theatre.
- **Live parse-time in ms.** You can compute it. Nobody scrolling a benefit section cares that it was 11 ms. Gimmick.
- **Scripted replay, typing, count-ups, exploding code.** You already know. Theatre.
- **Architect / process-owner toggle.** Correct UX, not a moment.
- **Competitor backlog vs your two columns.** Argument, and it reads as a swipe. You already made the point in prose.

---

### Rank and the call

1. **Provenance click-through** — the moment  
2. **Full frozen pyramid in the card** — the evidence, and the container for #1  
3. **Named-object roll-call** — cheap, native, proves the engine; does not prove the differentiator  
4. **Real BPMN artifact** — worth it only on top of #1  
5. **Ungated paste** — real wow, wrong surface, real risk  

**#1 is the one.** The page’s unsolved problem is not attention, it is disbelief that the left column is produced. Correspondence is the only wow this audience will not punish you for, it needs no Gemini on the open internet, it does not touch the approval gate, and it cannot be dismissed as a mockup without downloading the file and being wrong. #2 without #1 is a longer mockup. #3 without #1 is a better smartShift tile. #4 without #1 is a nicer graphic. #5 is a different product surface.

Build #1 + #2 as one card. Add #3 in the right column while you are there. Ignore the rest until a sceptical architect can click a sentence and see the `IF`.
