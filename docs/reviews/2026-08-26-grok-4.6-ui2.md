## Critical

**MFA is a UI gate on an already-issued Firebase session — and several paths skip it entirely**  
`components/LandingModals.tsx` (`handleSignIn`, `handleEmailSignIn`, `getRedirectResult`)

Firebase Auth succeeds *before* the TOTP check. The ID token is already valid. Nothing in this file sets a verified-MFA claim or signs the user out on a failed/abandoned check except the close button.

Concrete triggers:
1. User with `mfaEnabled` signs in → MFA modal appears → open `/dashboard` in another tab (or type the URL). Session is live.
2. Email sign-in: `getDoc(users/{uid})` is **not** in a try/catch. A Firestore error falls into the auth `catch`, shows “Invalid email or password”, **does not `signOut`**, and never shows MFA. User is signed in.
3. `getRedirectResult` on mount navigates straight to `/dashboard` with no MFA or profile bootstrap.

Whitepaper copy (“MFA gate on sensitive actions”) is false unless every API route/middleware independently requires a server-side MFA claim. Confirm by signing in an MFA user and requesting `/api/*` with the pre-MFA ID token.

## Medium

**Password sign-up stores `identityProvider: 'google'`**  
`components/LandingModals.tsx` — `handleEmailSignUp` `newProfile`

`authMethod` is `'password'` but `identityProvider` is hardcoded `'google'` (Google path is correct). Any rule/UI that keys off `identityProvider` will treat password users as Google users.

Trigger: email registration, then inspect `users/{uid}`.

**Title slide ignores `data.date` and prints today**  
`components/PresentationViewer.tsx` — `slide.type === 'title'`

```javascript
{data.author} • {new Date().toLocaleDateString()}
```

`PresentationData.date` is never shown. Re-opening an old deck shows the current calendar date.

**“Link copied” is shown even when the clipboard write failed**  
`components/GuideShareBar.tsx` — `handleCopy`

The `catch` path creates an `<input>`, selects it, removes it, and never copies (`execCommand` is not called). `setCopied(true)` still runs.

Trigger: deny clipboard permission (embedded browser / non-HTTPS iframe) → click Copy.

**ErrorBoundary “Try Again” cannot recover**  
`components/ErrorBoundary.tsx` — retry button

`setState({ hasError: false })` re-renders the same child instance that already threw. Without a remount `key`, React will immediately re-enter the error state.

Trigger: any render throw → Try Again.

**Mermaid effects can paint a stale chart**  
`components/MermaidDiagram.tsx` and the inner `Mermaid` in `components/ProcessDocumentation.tsx`

`mermaid.render` is async with no generation/abort flag. A fast `chart` change lets an older `render()` finish last and overwrite the new SVG (or the error HTML).

Trigger: switch process docs before the first render resolves.

**Whitepaper still leads with an unprovable speed claim**  
`app/whitepaper/page.tsx` — `benefitsEvidence` “Days → Minutes”

`ProofStrip`’s own comment says this class of claim was removed from the landing because it cannot be backed by shipped artifacts. The whitepaper (and PDF CTA) still states it as a benefit.

**Email `getDoc` failure masquerades as bad credentials** (related to the MFA issue above)  
`handleEmailSignIn`: Firestore throw → “Invalid email or password” while `auth.currentUser` is set.
