### Missing or invalid call counts are converted into “dormant” retire candidates
**Severity:** Blocking  
**File and line:** `lib/abap/usage-parser.ts:66-91`  
**Failure scenario:** Import a valid export containing `OBJECT_NAME` but no recognized call-count column, or a row with `CALLS=not available`. `parseCallCount()` returns `undefined`, but the parser stores `callCount: 0`; `joinUsageWithEvidence()` then classifies the object as dormant and `retire-candidate`, presenting absence of evidence as proof of zero use.  
**Fix:** Require a recognized call-count column, and reject or explicitly mark rows with unparseable counts as unknown. Never coerce missing usage measurements to zero.

### Missing standard or customer-prefixed ancestors are falsely reported as fully resolved
**Severity:** High  
**File and line:** `lib/abap/class-model-resolver.ts:38-67`  
**Failure scenario:** Upload `CLASS zcl_child DEFINITION INHERITING FROM zcl_missing.` without the parent source. Because `ZCL_MISSING` starts with `ZCL_`, it is not added to `missing`; the model returns `resolved: true`, and `detectStructural()` can publish “Inheritance chain fully resolved” even though the ancestor was never parsed. The same false success occurs for absent `CL_`, `CX_`, `IF_`, and `ZIF_` dependencies.  
**Fix:** Treat every referenced ancestor/interface absent from `nodesMap` as unresolved unless an authoritative external type resolver confirms it. Prefixes may identify likely object ownership, but cannot prove that the hierarchy was resolved.

### One differential-test flag marks every matching query as fully verified
**Severity:** High  
**File and line:** `lib/abap/complex-join-findings.ts:25-31`  
**Failure scenario:** A source contains two exact catalog matches, but only one query is result-differential tested. Passing `{ differentialVerified: true }` causes `verified` to be true for both queries, so both are labelled `fully` and no sign-off is required for the untested query.  
**Fix:** Supply verification per query using a stable source/file/line or query hash, and only upgrade the corresponding finding. A run-wide boolean must not establish query-level equivalence.

### Table-set matching recommends a CDS view without proving query semantics
**Severity:** High  
**File and line:** `lib/abap/cds-catalog.ts:22-38`  
**Failure scenario:** `SELECT ... FROM vbak CROSS JOIN vbap ...` or a join using an unrelated predicate has the exact table set `{VBAK, VBAP}`. `matchCdsView()` returns `I_SalesOrderItem` with confidence `0.95`, and downstream output recommends replacing the query with that view even though join keys, filters, cardinality, fields, and result semantics were never compared.  
**Fix:** Treat table-set overlap only as a low-confidence candidate. Raise confidence or recommend replacement only after validating join semantics and required fields against catalog metadata, or after a query-specific differential test.

### Ordered result differences are always ignored
**Severity:** High  
**File and line:** `lib/abap/result-diff.ts:39-83`  
**Failure scenario:** Comparing ABAP rows `[A, B]` with target rows `[B, A]` using the default options—or explicitly `{ unordered: false }`—returns `equal: true`, because both sides are always reduced to multisets and `opts.unordered` is never read. This can produce a false successful differential verification where row order is observable or required.  
**Fix:** When `unordered` is false or omitted, compare normalized rows positionally; use the multiset comparison only when `unordered: true` is explicitly requested.

### Internal-table INSERT without `TABLE` can become a critical database-write finding
**Severity:** High  
**File and line:** `lib/abap/evidence-model.ts:335-342`  
**Failure scenario:** Analyze a partial snippet such as `INSERT workarea INTO items.` where declarations are outside the upload. This is ABAP internal-table syntax, but `INTERNAL_TABLE_CLAUSE` only recognizes `INTO TABLE`; the detector consequently treats `WORKAREA` as an SAP database table and emits a Critical standard-table-write finding.  
**Fix:** Recognize `INSERT <wa> INTO <itab>` as an internal-table operation independently of declarations. Restrict database INSERT detection to unambiguous forms such as `INSERT <dbtab> FROM ...` and Open SQL `INSERT INTO <dbtab> ...`.

### Catalog freshness uses the newer timestamp although the union is only as fresh as its older source
**Severity:** Medium  
**File and line:** `lib/abap/catalog-service.ts:143-153`  
**Failure scenario:** The release artifact was fetched on January 1 and the classification artifact on February 1. `classifiedObjects` is computed from both, but `syncDate` is reported as February 1, implying the entire figure is current to that date even though half of its source data is a month older.  
**Fix:** Report both source dates, or use the earliest date as the “data current through” date for a combined figure.

### The reported measurement period is fabricated from first and last execution dates
**Severity:** Medium  
**File and line:** `lib/abap/usage-parser.ts:333-349`  
**Failure scenario:** A one-year SCMON export contains objects last used only on June 1 and June 2. `detectPeriod()` reports a one-day measurement period, even though those dates describe executions rather than the monitoring window; this incorrect period is then attached to every record and shown as usage context.  
**Fix:** Derive the measurement window only from explicit export metadata or user-supplied dates. If the export does not contain it, leave the period unknown and warn rather than inferring it from `lastUsed`.

### Decimal points can terminate SELECT extraction early
**Severity:** Medium  
**File and line:** `lib/abap/select-parser.ts:43-76`  
**Failure scenario:** A query containing an unquoted numeric literal such as `WHERE amount > 1.5` is terminated at the decimal point, so the extracted statement ends at `1`; joins and clauses after it are omitted or misparsed, leading to incorrect complexity and CDS-match findings.  
**Fix:** Use the ABAP tokenizer/parser for statement boundaries, or make the scanner distinguish decimal points and qualified syntax from the terminating period.
