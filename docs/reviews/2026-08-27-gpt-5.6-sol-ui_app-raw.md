## High

### The displayed Clean Core Score is recomputed from AI output and no longer matches the signed Run
- **Severity:** High
- **File and line:** `app/(app)/project/[projectId]/analyze/page.tsx`, `liveCleanCoreScore` calculation, around the comment `// ── Live-reconcile Clean Core Score ──`
- **Failure scenario:** The deterministic router records and signs a score of 40 in `/api/runs/create`. When the report renders, the client combines 60% newly derived coverage, 30% Gemini-generated `standardFit.potential`, and only 10% of the signed score. A model response of `"High"` can therefore make the customer-facing gauge show a substantially higher figure than the immutable Run and audit pack can prove.
- **Fix:** Display the server-authoritative `project.cleanCoreScore` from the active signed Run. If an alternative experimental score is useful, label it separately, explain its formula, and never present it as the Run’s compliance score.

### TCO page presents fabricated financial results from invented defaults and extrapolated source size
- **Severity:** High
- **File and line:** `app/(app)/project/[projectId]/tco/page.tsx`, state defaults and `calculations` memo (`setLoc(Math.max(1000, Math.min(lineCount * 10, 50000)))`, `scoreBefore = ... || 30`, `scoreAfter = 95`)
- **Failure scenario:** Opening TCO for a ten-line ABAP upload silently converts it to 1,000 LoC, assumes €900/€650 day rates, a €15,000 implementation, a 95 post-modernization score, and an 85% testing reduction. The page then shows exact “Annual Net Savings,” payback months, and ROI as if measured for that project, even though none of those inputs came from customer data or an executed assessment.
- **Fix:** Require users to enter or explicitly accept every business assumption, use the actual line count rather than multiplying it, and label outputs as scenario estimates with the complete formula and assumptions. Do not substitute a missing signed score with `30` or hard-code a 95 target.

### Delivery marks incomplete projects completed and “Ready for Deployment”
- **Severity:** High
- **File and line:** `app/(app)/project/[projectId]/delivery/page.tsx`, initial `fetchProject` effect and the `QA Status` block
- **Failure scenario:** A user navigates directly to `/project/{id}/delivery` after only creating an active analysis Run. Loading the page writes `status: 'completed'` without checking generated code, tests, documentation, test results, or architect sign-off, then unconditionally displays a green “Ready for Deployment” status.
- **Fix:** Derive completion server-side only after required artifacts and approvals are present. Render a blocked/incomplete state listing missing evidence, and reserve “Ready for Deployment” for an explicit, persisted deployment-readiness decision.

### Generated code is unconditionally labelled “AI Verified”
- **Severity:** High
- **File and line:** `app/(app)/project/[projectId]/transformation/page.tsx`, transformed-code panel header containing `AI Verified`
- **Failure scenario:** Gemini can return malformed, non-compiling, or semantically incorrect files; the transformation path merely parses the response and stores it, with a fallback that accepts arbitrary non-JSON text. Nevertheless, every transformed-code panel shows a green tick and “AI Verified,” despite no compiler, test runner, or deterministic validator having run.
- **Fix:** Remove the verification badge or replace it with “AI generated.” Show a verified state only after a named validator has actually executed and persist its result as evidence.

### The integrity report gives green success states for artifacts it never checks
- **Severity:** High
- **File and line:** `app/(app)/project/[projectId]/delivery/page.tsx`, `Integrity Report` list
- **Failure scenario:** A project with empty or malformed `generatedCode` and no documentation still receives green checks for “Transformed CAP Structure”/“abapGit Repo Layout” and “Enterprise BPMN Blueprint.” These checks are unconditional and do not inspect whether the relevant files or a valid BPMN document exist.
- **Fix:** Validate each artifact before rendering its status and show amber/red missing or invalid states. Ideally perform these checks server-side and attach their results to the active Run or delivery record.

## Medium

### MFA QR code is decorative and does not encode the enrollment URI
- **Severity:** Medium
- **File and line:** `app/(app)/settings/page.tsx`, `MockQrCode` component at the end of the file
- **Failure scenario:** `/api/mfa/setup/start` returns `qrCodeUrl`, but `MockQrCode` ignores its `value` prop and always renders the same hand-authored SVG pattern. Scanning it cannot enroll the returned TOTP secret, so users following the primary “Scan Authenticator QR” instruction fail setup unless they manually type the secret.
- **Fix:** Generate a real QR code from `qrCodeUrl` using a vetted QR encoder, or return a server-generated QR image. Do not display a QR-like graphic if it is not machine-readable.

### Local checkbox sign-off mathematically raises the displayed compliance score without evidence
- **Severity:** Medium
- **File and line:** `app/(app)/project/[projectId]/transformation/page.tsx`, `currentScore` calculation using `signedOffIds`
- **Failure scenario:** Starting from a signed score of 40, a user checks all local “sign-off” boxes and the Compliance HUD rises to 100%. The checkboxes are neither persisted nor tied to reviewer identity, justification, validation output, or a new signed Run, yet the result is presented as an overall compliance percentage.
- **Fix:** Keep the signed score immutable. Track review disposition separately, persist reviewer evidence server-side, and create a new signed assessment if reviewed evidence is intended to change a compliance metric.

### Empty test results produce a `NaN%` pass rate
- **Severity:** Medium
- **File and line:** `app/(app)/project/[projectId]/testing/page.tsx`, `getStats()`, `Math.round((passed / total) * 100)`
- **Failure scenario:** If test execution returns `[]`, `testResults` is truthy, `total` is zero, and the calculation divides `0 / 0`. The QA dashboard and chart receive `passRate: NaN`, resulting in an invalid customer-facing percentage or broken chart rendering.
- **Fix:** Treat an empty result set as “No tests executed” and avoid rendering pass/fail metrics until `total > 0`.

### Documentation generation crashes when hydrated analysis is an object
- **Severity:** Medium
- **File and line:** `app/(app)/project/[projectId]/documentation/page.tsx`, `generateDocumentation`, `Analysis Snippet: ${(project.analysis || '').substring(0, 1000)}`
- **Failure scenario:** Legacy or hydrated projects can carry structured `analysis` as an object. Clicking “Generate Blueprint” then calls `.substring()` on that object, throws before the Gemini request, and surfaces a generation failure despite valid analysis data being present.
- **Fix:** Normalize each context field first: use it directly when it is a string and `JSON.stringify` it when it is structured data, then truncate the resulting string.
