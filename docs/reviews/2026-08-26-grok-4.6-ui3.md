## Critical

**1. `UserOnboarding` — hook after a conditional return (SSR/client crash)**  
`components/UserOnboarding.tsx`, immediately after the `useState` block.

```ts
if (!auth) return null;

useEffect(() => {
  if (auth.currentUser?.displayName && !firstName && !lastName) {
```

`getAuth()` is documented as missing on the server. Next still pre-renders this client component: server render returns before `useEffect`; the browser then runs `useEffect`. React throws “Rendered more hooks than during the previous render” and the onboarding tree fails to hydrate.

**Trigger:** any page that mounts `UserOnboarding` (Firebase auth stubbed/null on SSR, defined in the browser).

Fix: call `useEffect` unconditionally; gate the body on `auth`.

**3. `useUserProfile` — `onAuthStateChanged` is `async`, so the Firestore listener is never unsubscribed**  
`hooks/useUserProfile.ts`, the `useEffect` auth callback.

```ts
const unsubscribeAuth = auth.onAuthStateChanged(async (user) => {
  // ...
  const unsubscribeProfile = onSnapshot(userDocRef, ...);
  return () => unsubscribeProfile(); // ignored: async callback returns a Promise
});
return () => unsubscribeAuth();
```

Firebase does not treat a Promise as snapshot cleanup. Every auth event leaks another `users/{uid}` listener; unmount does not detach it; `setProfile` can run after unmount.

**Trigger:** sign-in, token refresh, or navigating away from any tree that uses this hook.

**8. `EvidenceSweep` — empty findings never complete; completion timeouts are not cleared**  
`components/analyze/EvidenceSweep.tsx`.


If `isActive === true` and `findings` is `[]`, `onComplete` is never called (parent can hang). The `setTimeout` in `finishSweep` (600ms), the min-duration wait, and the reduced-motion 100ms wait are not cleared on unmount/dep change, so `onComplete` can still fire on a stale sweep.
