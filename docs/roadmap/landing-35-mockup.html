From code to process

What does this program actually do?

Clean-Core.io draws the process the code runs as a map you can walk through, and writes what it does in plain words, with every sentence pointing to its line.

  • BusinessThe steps in your words, who is involved, and how a case can end.
  • ITEvery element carries its line, read by the engine before any model.
  • ManagementWhat the program is for, before anyone decides about it.
For IT How the map is built, and what leaves as a file ▾
  • A deterministic ABAP engine parses the program first — no model. The same file gives the same map. Start and end events, tasks, decision points and sub-processes each carry a line anchor, or the reason they have none.
  • Business names come from a model only with the engine's facts per element, swap in visibly and carry the ✎ AI-generated mark. Without facts, the engine's own label stays.
  • Object-oriented programs: classes, methods and a status field with its transitions read as the process; technical methods fold into their caller.
  • Full screen with the step list, search and an Edit switch; every save is a new revision, the reconstruction stays revision 1.
  • Export and import as standard BPMN 2.0 XML. Import into SAP Signavio is not verified; there is no connection to a Signavio workspace.

How far is it from a clean core, and where can it go?

Clean core keeps SAP standard untouched: extensions use only what SAP releases for them. Clean-Core.io shows, object by object, how far a program is from that, and the route that fits.

The decision

What do we risk, and what do we decide?

Keep it, rebuild it, move to SAP standard or retire it. Clean-Core.io gives an indication with its reasons — the decision stays yours.

  • BusinessThe open questions that block a decision, in plain words.
  • ITOne rule per object decides its bucket; every assignment shows its evidence.
  • ManagementEverything on one page: indication, risk, options, next steps.
For IT Four buckets, one rule per object ▾
Retire

The rule it serves is confirmed "Drop", or usage data shows no execution over at least 13 months — a candidate, not a verdict.

No catalogued path

Needed, below the target's bar, and SAP names no released API and no successor.

Rebuild

Needed, below the bar, a successor or extension path named — and every own write to an SAP table.

Keep

Needed and permitted on the target platform.

The first rule that applies wins. Why 13 months: period-end and year-end programs run once a year.

FAQ

Questions people ask before they start

Is there a demo without an account?

▾

Yes. A two-minute demo at /demo shows one program read end to end, no account. The interactive demo project lives in your workspace and needs a free account.

What does it cost?

▾

Nothing. Clean-Core.io is a free community project with no paid tier, and we accept no payment. An account has five analysis runs; each starter example is free the first time you run it. After that you continue with your own model key, which its provider bills under your own agreement.

Is my code kept confidential?

▾

Only the account that created a project, and anyone that account invites, can open it. An invitation is bound to one confirmed e-mail address, gives read access and can be withdrawn at any time. There are no public links. We do not sell, rent or commercially use your code.

Where is my code stored, and what leaves it?

▾

Stored in the EU — Google Cloud, Belgium (europe-west1). The engine reads it without a model; text and code drafts are written by the model provider, reached only through our server — Google Gemini, or the provider of your own key. No analytics, advertising or tracking cookies.

Is my code used to train models?

▾

With our community key, Google does not use your code to train its models — the paid Gemini API terms apply. With your own key, the terms of your own account with that key's provider apply.

What is SAP clean core?

▾

Clean core keeps the SAP S/4HANA standard unmodified: extensions use only released, upgrade-stable interfaces — in-app with ABAP Cloud or side-by-side on SAP BTP, part of the SAP Business AI Platform. SAP's clean core level concept grades what an extension uses from A (released APIs and extension points) to D (not recommended: modifications, implicit enhancements, writes to SAP tables).

Is the generated code ready to go live?

▾

No. It is a draft for a person to review. CAP tests run in an isolated runner against mocks, not in a real SAP S/4HANA system; RAP tests are an ABAP Unit class that runs only in your own system. A signed run proves where a result came from and that it has not changed — not that it is correct.

Does it replace ABAP Test Cockpit or SAP's own tools?

▾

No. ABAP Test Cockpit stays the check to rely on; the level Clean-Core.io shows is an orientation. SAP's agents tell developers what to fix; Clean-Core.io shows the business what the code does and carries the evidence to a decision.

Does it work with SAP Signavio?

▾

Clean-Core.io exchanges standard BPMN 2.0 XML files. Import into SAP Signavio has not been verified yet, so we do not claim it, and there is no connection to a Signavio workspace.

Is Clean-Core.io an SAP product?

▾

No. It is an independent community project, not affiliated with or endorsed by SAP SE. It follows SAP's clean core level concept and reads SAP's published Cloudification Repository.

Measurement without third parties — owner and lawyer decision

  • Option 0 — nothing new. No change to the privacy texts.
  • Option A — counts the server already has (recommended first). Per day: new accounts, accounts with a first project, first signed runs (own code vs example), showcase chapters requested. Read as aggregates from Firestore and the access logs; no cookie, no identifier, no client code.
  • Option B — a first-party click counter. A request to our own origin carrying only an event name (section reached, button id, dialog opened); the server increments a daily counter and stores no IP, no identifier, no user agent. Measures stages 0, 1 and 5 on the landing — the same mechanism the showcase proposes for its chapters (a 204 beacon to its own origin, e.g. /api/demo-count), so there is one decision for both pages.

Legal: the Privacy Policy §7 says today "no performance or usage measurement", and §9 says server logs are not used "to analyse your behaviour". Option A uses the logs for a new purpose (aggregated statistics) and needs a line in §9; option B contradicts §7 and needs §7 rewritten (likely Art. 6(1)(f) GDPR; § 25 TDDDG: with no storage on and no read from the device, no consent banner — the lawyer to confirm). Either way a "signed-out visit contacts only its own origin" stays true; no analytics script, no pixel.
