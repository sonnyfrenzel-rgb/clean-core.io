What is Clean-Core.io?

Clean-Core.io is a free community tool for SAP custom code: a deterministic ABAP static code analysis reads your program, reconstructs its business process with a line anchor on every element, shows SAP's clean core level for each SAP object it uses, and seals every analysis as a signed run.

From code to process

How is the process reconstructed from ABAP?

Clean-Core.io draws the process as BPMN from what the ABAP code does, puts a line anchor on every element, and names what the code cannot show instead of drawing it.

Large processes stay readable

Levels instead of zoom: the map opens as an overview of phases. Open a phase in place, follow the path at the top, or show only the paths that lead to one step. Try it on the 1,000-line example — with the mouse, the keyboard, or as a list of steps.

Mit Release 3.0 kommt diese Übersicht aus dem echten Lauf des Beispiels, bei jedem Release neu erzeugt (Roadmap 3.0.6); kein Mockup-Bild geht live.

Every element points to its lines

Start and end events, tasks, decisions and sub-processes each carry a line anchor. Decisions keep their condition from the code; proposed lanes are marked as proposals, never as your organisation.

Business rules come out of the code

Literals in conditions — tolerances, plants, vendor lists, date limits — become rule candidates with their anchor. You keep, change or drop each one, or move it to customizing.

Unreached code is named, not drawn

Forms no entry point calls stay off the map and are listed underneath with their lines. Identical forms are grouped, technical helpers fold into their caller.

Exchanged as BPMN 2.0 XML files

Export and import standard BPMN 2.0 XML; collapsed sub-processes stay real sub-processes. Import into SAP Signavio has not been verified yet. There is no connection to a Signavio workspace — only files.

Honest by design

How do I know what is proven and what is not?

Every statement carries its source as a word, an icon and a shape. Nothing simulated passes as proven: missing stays missing, simulated stays simulated, reconstructed stays reconstructed.

Where a statement comes from

One fixed list. The shape says how firm a statement is.

Filledsettled

Backed by the engine, a signature or a real run.
Confirmed by your account — a self-declaration, not a mandate.
No longer current — recalculate. Stale is not wrong.

Outlinederived or imported

Derived from the code, not yet confirmed.
Taken from a file: ATC results, usage data, SAP's catalogs.
Could not be determined — always with its reason.

Dashedprovisional

Suggested by a language model, unchecked.
Calculated on your own assumptions.
Shown against mocks, not against a real system.

Four buckets, one rule per object

The first rule that applies wins, and every assignment shows its evidence. The buckets depend on the project's target platform.

Retire

The rule it serves is confirmed “Drop”, or a usage import shows no executions for at least 13 months.

Why 13 months: period-end and year-end programs run once a year. A shorter window never retires an object: “Usage window too short: 4 months — needs 13.”

Keep

Needed and allowed on the target platform: Public Edition level A only, Private Edition A or B.

Rebuild

Needed, level C or D, with a successor or an extension path — and every modification or own write to SAP tables. That is your work, never SAP's.

Blocked by SAP

Needed, level C or D, and an SAP catalog object with no released successor and no extension path — SAP's roadmap, not your homework.

The same level B object is Keep in Private Edition and Rebuild or Blocked by SAP in Public Edition. Change the target platform and the page says what moved.

Next to your SAP tools

Does it replace SAP's own tools?

No. ABAP Test Cockpit stays the authoritative check and ADT stays where code is built and tested; Clean-Core.io prepares the evidence and the decision around them.

SAP toolWhat it is forHow Clean-Core.io relates
ABAP Test Cockpit (ATC)The authoritative check for clean core violations — keep using it.Reads the same SAP Cloudification Repository (33,864 classified objects) and shows its reading as level A–D. Import ATC results to compare them with the engine.
ABAP Development Tools (ADT)Where ABAP is developed, compiled and unit-tested; ABAP Unit and the CDS Test Double Framework are on board.Generated drafts arrive as an abapGit package that you import, compile and test there.
SAP SignavioProcess modelling, under its own licence.Exchange of BPMN 2.0 XML files. Import into SAP Signavio has not been verified yet; there is no connection to a Signavio workspace.
SAP Cloud ALMProject and application lifecycle, under SAP's licence.No adapter. The handover package is a set of files you take along.
