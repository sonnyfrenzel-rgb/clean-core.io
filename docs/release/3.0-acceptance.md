# Clean-Core.io 3.0 — acceptance protocol

**Release planned:** Wednesday 07.10.2026 · **Protocol state:** 02.10.2026 at `e450d31c`
(`integrate/next-3.0`, one docs commit ahead of `dev` at `6637a983`) · **Last release on
`main`:** v2.20.0 (`fc787674`), 850 commits and 154 merges behind.

This protocol is a preparation, not a verdict. The owner is still reviewing the product,
and four branches are still in flight (below), so every "green" means *green at the commit
named*, and the release commit has to be run again. The binding conditions come from
`docs/ROADMAP.md` §4 ("3.0 — Switch-over", "Done when", acceptance order) and §15 (gates
G0–G4); the external checklist is the Codex synthesis of 02.10.2026 (`C:\Review\codex-out\report.md`,
commit `187ccbce`, verdict "not releasable" at that commit). Security details of open
findings stay out of this file.

**Legend.** *Status* — **green**: the evidence holds at the commit named · **open**: work or
a check is still to be done by an agent · **Sonny**: needs the owner (a decision, an account,
a console or the `main` go). *Who* — **CI**: the `validate` job of `.github/workflows/deploy.yml`
· **agent**: a Claude session, locally or on `dev` · **Sonny**: only the owner can do it.

## 0. How to run the evidence

| What | Command | Needs |
|---|---|---|
| Source guards of every row | `npx --yes --package=node@22 -- node scripts/release/acceptance.mjs` | nothing but the tree (about 90 s) |
| Rendered and emulator specs of every row | `npx --yes --package=node@22 -- node scripts/release/acceptance.mjs --mode all --serve 3531` | emulators on :9099/:8080 already running; a build made with `NEXT_PUBLIC_USE_FIREBASE_EMULATOR=true` |
| One row | `… acceptance.mjs --rows 3.0.10,G2 --mode all --serve 3531` | as above |
| What runs for which row | `node scripts/release/acceptance.mjs --list` | — |
| The whole suite, as CI | `npx playwright test` on Node 22, one worker (CI: `workers: 1`, `retries: 2`) | emulators, a server (Playwright's own `webServer`) |
| Text step size | `node scripts/release/text-scan.mjs --write` → `docs/release/3.0-text-scan.md` | — |

The script writes `.release/acceptance-<sha>.md` (gitignored), one line per row of this
protocol. It blanks every mail and model key for its children, forces the emulator hosts,
refuses a base URL on `clean-core.io` or `*.run.app`, and refuses `--serve` on 3000/3300.
Two local artefacts it avoids on purpose, both reproduced on 02.10.2026: on Node 20
`tests/generation-follows-contract.spec.ts` fails with "Unexpected token 'export'" (passes on
Node 22, as in CI); with parallel workers `tests/workspace-print-sheet.spec.ts` races on a
shared esbuild output file (`tmp/workspace-print-sheet/*.cjs`) and reads a half-written
bundle — hence one worker by default. The race is a test-harness defect worth a small fix
(per-worker output directory); it is not a product failure and CI never sees it.

**Dry run, 02.10.2026, `e450d31c`, source mode, Node 22, one worker:** 34 spec files, 924
tests passed, 0 failed, 3 fixme (the 3.0.8 armed trio); 5 rows pass outright, 25 are partial
or not run (their rendered specs need `--mode all`), 2 are manual only. Beyond the rows, all
230 source-only spec files of the suite on Node 22 with four workers: 3,754 passed, 1 failed
(the print-sheet race above), 3 skipped. **Last full CI run
with a result:** `33f825fe` (run 36996352483) — 7,014 passed, 1 failed
(`tests/registration-email-guard.spec.ts`, welcome mail 518 words; fixed by `c9e72066`, whose
run and the one of `6637a983` were still in progress when this was written).
